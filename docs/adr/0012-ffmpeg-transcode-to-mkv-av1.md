# 下載完成後新增一道獨立的 ffmpeg 轉檔步驟，統一輸出 MKV/AV1

ADR-0002 決定下載與解密維持純 JS/Node、不依賴 ffmpeg，理由是原始 segment 直接位元組串接就能得到合法輸出，不需要 remux。這個決定對「下載」本身仍然成立，本 ADR 不推翻它——`downloadToFile` 還是純 JS 串接。但使用者現在需要下載結果統一是 MKV 容器、AV1 影像編碼（原始來源格式五花八門，副檔名也常常跟實際內容對不上），這是 ADR-0002 涵蓋範圍之外的新需求：純位元組串接做不到「改變編碼」，只有 remux/re-encode 工具才行。因此新增 ffmpeg 作為下載完成後、搬移到 Destination Folder 之前的一個獨立轉檔步驟（見 CONTEXT.md 的 Transcode 詞條），透過全域設定開關控制是否套用；影像軌用 `libsvtav1` 重新編碼，音訊軌 stream copy 不重壓，轉檔成功後刪除轉檔前的原始檔並強制副檔名為 `.mkv`。

## Considered options

- 純軟體編碼（`libsvtav1`）vs 硬體加速（VAAPI/NVENC/QSV）：硬體加速速度快很多，但畫質可控性較差，且這個工具的實際部署主機規格未知（單人自架、可能是任何機器），沒辦法保證都有對應硬體，也還要多處理容器要不要掛 `/dev/dri` 之類的裝置。選純軟體 `libsvtav1` 換取跨環境一致、可預期的行為，犧牲部分速度；日後若需要可再加硬體加速為可選項。
- 轉檔前偵測來源是否已經是 AV1、跳過重複編碼：需要多一道 `ffprobe` 檢查，換來的節省在目前使用情境下不常發生（來源多半不是 AV1）。第一版選擇一律重新編碼，先把範圍做小。
