# 目的資料夾允許巢狀子目錄，修訂 ADR-0005 的扁平目錄限制

ADR-0005 原本讓 `DOWNLOADS_DIR` 維持扁平目錄，理由是簡化撞名檢查、讓使用者在目的地看到的檔名跟自己輸入的一致。新增「目的資料夾選擇」功能後，使用者在送出下載前可以選擇（或新建）任意深度的 `DOWNLOADS_DIR` 子資料夾作為 Destination Folder，用來組織分類下載的檔案。撞名檢查改為 per-folder（同資料夾內查重，不同資料夾同檔名不衝突）；`relocateFile` 的目的路徑多一段子資料夾，rename → EXDEV fallback → copyFile 的搬移邏輯本身不受影響。檔名仍然完全等於使用者輸入的內容，ADR-0005 的這一半精神不變。

## Considered options

- **維持扁平目錄、只在數個預先設定好的根目錄中選一個**：不需要巢狀導航 UI，但無法讓使用者依內容分類（例如「電影／2024」），彈性不足。
- **允許自由輸入任意絕對路徑**：最有彈性，但完全繞過 `DOWNLOADS_DIR` 邊界，使用者可能打錯路徑寫到非預期位置。

## Consequences

- 撞名檢查需要知道目的資料夾，不能只查 `DOWNLOADS_DIR` 根目錄。
- 下載歷史列表需要顯示每筆記錄存放的子資料夾路徑，否則使用者事後找不到檔案。
- 需要新增列出／建立子資料夾的後端 API，並對子資料夾路徑做跟檔名一樣的字元清洗與防目錄穿越（`..`）處理。
